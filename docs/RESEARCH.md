# Focused research · 9 September 2026

Research informs hypotheses; the Lab must test them. No reference assets, layouts, characters or proprietary spell designs are used.

| Question                  | Evidence                                                                                                                                                                                                                                                                                                | Lab hypothesis                                                                                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Input economy             | A Ravenswatch developer confirms rebinding in the [controls thread](https://steamcommunity.com/app/2071280/discussions/0/796715232585071292/). The accompanying user-posted layout lists WASD, Space, LMB attack and RMB power. The layout is corroborating community evidence, not an official manual. | Keep conventional movement/aimed actions; add alternate physical bindings to the same semantic actions. No essential wheel or side button.                                                    |
| Laptop pointing           | [Microsoft's Surface guidance](https://support.microsoft.com/en-us/surface/cover-keyboard/surface-touchpad-use-and-settings) describes one-finger click/movement and two-finger secondary actions; touchpad settings can suppress accidental touches.                                                   | Do not equate browser mouse events with validated physical trackpad behavior. F/K Secondary and J repeat Primary make clicks optional; simultaneous typing/aiming remains hardware dependent. |
| Cursor readability        | [Supergiant's Hades II support guide](https://www.supergiantgames.com/faqs/hades-ii/) discusses pointer size, mouse lock and input latency.                                                                                                                                                             | Keep a visible world cursor, no camera rotation/lock, and test projection under movement and resizing.                                                                                        |
| Composable magic          | [Mystralia developer article](https://blog.playstation.com/?p=193386) describes behavior, augment and trigger categories and emphasizes iteration toward depth without overwhelming new players.                                                                                                        | Separate operations from delivery geometry. Future modifiers should attach to compatible events. Do not add a spell editor before base actions prove useful.                                  |
| Emergence from simulation | [Petri Purho's Noita GDC session overview](https://www.gdcvault.com/play/1025695/Exploring-the-Tech-and-Design) presents integration of materials and rigid bodies to generate emergent play. Only the public overview was consulted; no claim to have watched the full talk.                           | Share heat, water, cohesion and momentum rules across targets. Use Rapier for mass/collision, not a costly falling-sand simulation.                                                           |
| Complexity cost           | [Magicka design talk overview](https://www.gdcvault.com/play/1019446/Keep-It-Complex-Stupid-Creating) argues that complexity can support emergence, in a service-game context.                                                                                                                          | Complexity is not inherently bad, but count useful consequences per rule. Avoid filling an elemental matrix. This is an inference, not a result of that talk.                                 |
| Browser implementation    | [Rapier character controller](https://rapier.rs/docs/user_guides/javascript/character_controller/) and [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html) document collision-controlled movement and WebGL 2 rendering.                                                        | Fixed 60 Hz rules; explicit collision adapter; render statistics and context-loss handling.                                                                                                   |

No credible exact camera pitch, character footprint or cast timing measurements were established for the reference games. Do not invent those numbers. The Lab tests our own 37°/51°/64° camera pitches and three bounded tempo presets. Primary repeat avoids repeated clicking; no separate charged grammar is introduced.

Selective research stopped once it supplied testable choices. Other listed references remain future resources, not a checklist to claim familiarity with.

## Co-op API check (2026-09-09)

Consulted current [official Trystero repository/API](https://github.com/dmotz/trystero) and [documentation](https://trystero.dev/docs/), then checked installed 0.25.4 source/types. `makeAction` returns `{send,onMessage}`; peer callbacks are assigned on Room; handshake callbacks validate version/host/guest before admission. Default Nostr offers account-free signaling, while the official ws-relay package provides a loopback signaling server for repeatable tests. Gameplay uses WebRTC data channels in both cases. No TURN is provisioned; STUN/signaling alone cannot guarantee restrictive-network reachability. No reference-game resurvey or external assets were needed.
